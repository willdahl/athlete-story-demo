# Athlete Stories

A judge-accessible prototype for turning an athletic event into a visual story: short form → interview → review moments → attach photos → preview and approve.

## Try it

Open [the hosted demo](https://athlete-stories-will-demo.cheeky-field-8475.chatgpt.site). Start a story about your own ride, run, hike or walk, or open a clearly labeled fictional cycling/hiking example. Try changing an answer, inspect source answers, edit a moment, approve it, attach a photo and preview the story. Reload to resume a saved story in the same browser.

## What actually works

- Live, adaptive OpenRouter interviews without sign-in, with an explicit browser-local mock mode.
- Source-linked AI drafts, a second model review, before/after comparison, editing and athlete approval.
- Private Supabase story storage and photo uploads, plus a browser recovery copy.
- Optional photo context, moment tagging and full-image display.
- Training metrics default to miles. Weekly charts require supplied weekly records.
- Curated Alex showcase and independently editable Alex/first-5K seed copies.

Live requests use a server-held OpenRouter key. Answers go to OpenRouter; images do not. Source IDs are checked and original evidence is attached by code. This provides traceability, not a guarantee of accurate interpretation; athlete review remains required. Approving a story does not publish it publicly.

Activity connectors and image/video generation remain future work. Examples and illustrations are synthetic. Exported cloud-photo URLs are shared demo links; JSON export does not bundle downloaded cloud image bytes. Browser copies remain in the browser profile and can be removed with site data.

## Run locally

For mock-only UI work:

```sh
npm ci
npm test
npm run preview
```

For the live server, follow [LIVE_SERVICE.md](LIVE_SERVICE.md). CLI authentication and migrations are documented in [supabase/README.md](supabase/README.md). Credentials stay outside Git. The production service is a shared fictional demo without sign-in; Supabase CLI login is only for database administration.

## Source structure

- `dist/app.js`, `index.html`, `styles.css`: athlete workflow and viewing experience.
- `dist/interview.js`: bounded interview rules and evidence-linked moment proposals.
- `dist/examples.js`: explicitly fictional scenarios.
- `dist/charts.js`: deterministic metrics and chart rendering.
- `dist/storage.js`: IndexedDB persistence adapter.
- `dist/live.js`: shared demo API and photo upload client.
- `server/lib/story-agent.mjs`: interview, drafting, editorial review and evidence validation.
- `server/lib/story-api.mjs`: authenticated, owner-scoped cloud API.
- `supabase/migrations/`: versioned database schema and access restrictions.
- `test/`: behavior and provenance checks.
- `.github/workflows/pages.yml`: automated tests.

The browser assets can run in mock mode on a static host. Live mode requires the supported Sites server in `server/`. The working project’s private transcripts and authoring materials are intentionally excluded from this repository.

## Finished STP example

`dist/stp/` contains a curated fictional STP story with the interactive journey map and synthetic training ledger developed before this workflow demo. It demonstrates the intended storytelling output. It was prepared through iterative interview/editorial work, not automatically generated by the deterministic mock. Only the selected display copy and synthetic training records are included; working transcripts, interview prompts, source-turn identifiers and rejected editorial candidates are omitted. Its generated images are illustrations. The map displays Cascade’s published 2026 event route as context, not a participant GPS track; private-stop and travel positions are illustrative.

## Visual story experience

Created stories now use the Alex-inspired journey layout: a persistent moment navigator, overview story and preparation panes, image-led moment views, and a lower map area. When no locations are supplied, the lower area shows the ordered moments instead of inventing a route. Review offers optional people/context and latitude/longitude fields. Only approved moments appear; changing those details requires approval again. Photos expand for closer viewing. The STP example remains the curated reference and primary entry point.

## Seeded walkthroughs

The home page now offers three lanes: the unchanged completed Alex showcase, an editable Alex walkthrough, and the user-supplied mock first-5K interview. Each walkthrough creates a new browser-local project with independent IDs and copies of its inputs. Entry points are Interview, Review moments, Photos, and Preview. Starting a fresh copy preserves existing copies.

The Alex seed includes the roleplay questions/answers intentionally selected for this demo, reviewed direct-address copy, synthetic training data, generated images, and illustrative course context. Internal chat IDs and working editorial documents remain excluded. Unlike the read-only STP showcase, this seed intentionally exposes the roleplay answers for editing. Recalled training figures remain distinct from ledger values. Changing the event or activity hides inherited STP geography.

The first-5K seed retains the supplied interview text and spelling. “Skip,” “I just did,” and the request for help drawing insights remain in the interview but are excluded from draft moments. No reflection, precise route, training totals, or images are invented.

Editing an answer invalidates affected approvals. Review proposed changes shows current versus proposed wording before applying. In mock mode, changed moments use verbatim answers rather than generating new prose; untouched curated moments retain their wording and media. Before applying, previous moments are retained in exported history. Removed-moment photos remain available for retagging.
